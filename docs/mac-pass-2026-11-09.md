## 4. Firefox's memory on the Mac (7.4.2, 7.4.3)

### The FIFO, checked by hand

`.work/fifo-probe/probe.mjs` (not in Git) launches Playwright's Firefox 155 with `memory_info_dumper.watch_fifo.enabled` set,
then loads a page holding 120 MB of garbage. It writes the dumper's commands into the FIFO and reads the report.

* **Where the FIFO is.** The lead said the profile directory, and it was not there. Gecko made `debug_info_trigger` in its
  temp directory (`$TMPDIR`, here `/var/folders/…/T/`), which the user's own Firefox would share. With
  `memory_info_dumper.watch_fifo.directory` set to a fresh directory and written **before** the enable preference, the FIFO
  is made there. Written after it, the directory was ignored: the watcher starts the moment it is enabled.
* **The reports.** Each command produced `$TMPDIR/unified-memory-report-<id>-<pid>.json.gz` about 1.0 s after it was written,
  the same file Linux gets after the signal (`memory/fifo-probe.txt`). The page's JS GC heap read:

  | FIFO command | page's JS GC heap |
  | --- | ---: |
  | `memory report` | 128.6 MB |
  | `minimize memory report`, straight after | **0.2 MB** |
  | `memory report`, after new garbage | 117.6 MB |

  The minimize collected the garbage, as SIGRTMIN+1 does on Linux. The plain report did not collect.

### The tool change

A new module, `scripts/gecko-report-trigger.mjs`, holds the platform split. `map-memory-census.mjs` and `session-hour.mjs`
call it where they sent the signal:

* `geckoReportPrefs()` returns `{}` on Linux. On macOS it returns the FIFO directory (a fresh `mkdtemp` directory under
  `$TMPDIR` for each run) and the enable preference, in that order. They are spread first into the tools'
  `firefoxUserPrefs`.
* `requestGeckoReport(pid, minimize)` sends `process.kill(pid, minimize ? 35 : 34)` on Linux, as before. On macOS it writes
  `minimize memory report` or `memory report` into the run's FIFO. It waits up to 30 s for a FIFO no older than the launch,
  and retries while the FIFO has no reader yet (`ENXIO`).
* The Firefox gate now admits Linux and macOS. `treeRss` returns null off Linux: it reads `/proc`, and before this change it
  was reached only on Linux, because `browserPid` stayed 0 elsewhere. The census's `--gc-logs` (SIGRTMIN+2, Gecko's GC and
  CC edge logs) stays Linux only, with an error, because its FIFO equivalent was not checked. The run's FIFO directory is
  removed when the browser closes.

**Linux behaviour unchanged.** `git diff` of the two tools shows every Linux path unchanged except two lines:
- the signal is sent through `requestGeckoReport`, which on Linux sends the same `process.kill(browserPid, 35 | 34)`;

**Explained afterwards (Linux, 2026-11-10): the wheel and the belt.** Playwright's WebKit builds a synthetic wheel's ticks from
WebKit's 40-pixel line. Its `WebPageInspectorInputAgent::dispatchWheelEvent` (Playwright's `browser_patches/webkit`) sets

120 (`WheelEvent.cpp`, `TickMultiplier`). So the spec's 100 pixels read −300, which the page takes as 2.5 notches: two belt steps
and a half-notch remainder, `items[2]`. This is the harness, not Play. A real Safari wheel's ticks come from the platform.

## Open and unexplained

* **The host.** It was under memory pressure through the whole pass (swap 15.8 to 17.7 GB, the unidentified VM, the user's
  video).
  The Firefox FAILs in 7.2.4, 7.3.2 and 7.3.3 come with the evidence above: starved frames, and a uniform slowdown of
  Firefox's loads while Chromium's held. That evidence does not prove the host is the whole cause. Rerunning those rows on a
  quiet host is what a clean verdict needs.
* **`--gclog` collects nothing** in Playwright's Firefox 155 on the Mac. Whether it ever collected anything on Linux was not
  checked here. Until it is fixed, a GC attribution for a Firefox roam needs `--profile`.
* **The 40 s collection.** Every Island roam has a major collection about 40 s in. Its slices between frames take 28 to 101
  ms (`INTER_SLICE_GC`, `TOO_MUCH_MALLOC`, `TOO_MUCH_JIT_CODE`), and on their own they make two to four gaps over 50 ms in
  that window. That is enough to spend the 50 ms budget of a short roam even on a quiet host. This is the part of 7.2.4 the
  Play code can act on.
* **The suite.** Chromium's `instructor-conversation` fails on the Mac twice out of two, and passes in Firefox here and in
  Chromium on Linux. WebKit's wheel-and-belt failure was the harness (explained on Linux, 2026-11-10, [step 5](#webkit-714)).
  `gameplay`'s inspect race was open between Play (drop the frame in flight) and the spec (wait for it). The stale specs
  (`lighting` and `mirrors` sizing in Firefox, `no-webgl` and `software-renderer` in WebKit) were not changed: the brief allowed
  no change outside step 4. Linux changed the specs on 2026-11-10, the inspect case among them; the Mac has not rerun them.
* **Real Safari** was not run (the user skipped it). Its checklist is in [step 5](#real-safari-714).
* **The Ship in the Firefox hour.** Its second reading is 233 MB below its first; what was released between the two is open.
